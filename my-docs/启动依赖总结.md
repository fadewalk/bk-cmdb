# bk-cmdb 启动依赖与本地启动总结

> 本文根据当前仓库的启动文档、构建脚本、配置模板和服务初始化代码整理。
>
> 适用分支：`v3.14.x`

## 一、结论概览

bk-cmdb 不是单体应用，而是一组 Go 微服务。后端运行起来至少需要以下三个外部服务：

- ZooKeeper：服务注册发现和配置中心
- MongoDB：CMDB 主数据库
- Redis：缓存、Session 以及数据采集相关队列

如果从源码编译，还需要 Go、Node.js/npm、Python、Make、Bash 以及编译工具链。

Elasticsearch、Monstache、Kafka、IAM、GSE、PaaS/Login、bk-secrets 和 API Gateway 都是按功能启用的可选依赖，不是最小本地启动组合的必需项。

---

## 二、运行时依赖

### 2.1 必需依赖

| 依赖 | 作用 | 默认端口/要求 |
|---|---|---|
| ZooKeeper | 服务注册发现、配置中心 | `2181` |
| MongoDB | CMDB 主数据库、事件监听数据 | `27017`；必须配置 Replica Set，默认名称为 `rs0` |
| Redis | 缓存、登录 Session、主机快照/发现/硬件采集数据 | `6379` |
| Python | 执行 `init.py` 等初始化脚本 | 建议使用 Python 3；旧文档曾建议 Python 2 |

项目部署文档中列出的最低版本为：

- ZooKeeper `>= 3.4.11`
- Redis `>= 3.2.11`
- MongoDB `>= 4.2`

> MongoDB 必须能够提供 Primary。未配置或未初始化 Replica Set 时，执行 `init_db.sh` 可能出现 `ReplicaSetNoPrimary`。

### 2.2 可选依赖

| 依赖 | 启用条件 | 作用 |
|---|---|---|
| Elasticsearch | `es.fullTextSearch: "on"` | 全文检索 |
| Monstache | 启用全文检索 | 监听 MongoDB 并同步数据到 Elasticsearch；需要配套插件 |
| Kafka | `datacollection.hostsnap.reportMode: kafka` | 主机快照消息消费 |
| 蓝鲸 IAM | `--auth_enabled true` 且鉴权模式为 `iam` | 权限中心鉴权 |
| 蓝鲸 PaaS/Login/ESB | 使用 `blueking` 登录、ESB 或蓝鲸集成能力 | 登录、组件 API 和相关平台调用 |
| GSE | 开启主机身份下发 | 查询 Agent 状态和下发主机身份文件 |
| API Gateway | 蓝鲸部署方式、通知或 GSE v2 场景 | 访问蓝鲸 API Gateway |
| bk-secrets | `cloudServer.cryptor.enableCryptor: true` | 云账号信息加解密 |

## 三、CMDB 微服务

完整启动通常包括以下服务：

```text
cmdb_adminserver
cmdb_apiserver
cmdb_coreservice
cmdb_datacollection
cmdb_eventserver
cmdb_hostserver
cmdb_operationserver
cmdb_procserver
cmdb_taskserver
cmdb_toposerver
cmdb_webserver
```

`scripts/start.sh` 会遍历构建产物目录下的 `cmdb_*` 目录并启动服务。

同步服务默认不启动，需要显式指定：

```bash
./start.sh --with-synchronize
```

### 3.1 默认服务端口

| 服务 | 默认端口 | 主要作用 |
|---|---:|---|
| `cmdb_adminserver` | `60004` | 配置管理、数据库迁移和初始化 |
| `cmdb_apiserver` | `8080` | API 网关/场景 API 入口 |
| `cmdb_coreservice` | `50009` | 核心资源管理原子接口 |
| `cmdb_datacollection` | `60005` | 数据采集和消息处理 |
| `cmdb_eventserver` | `60009` | 事件推送、主机身份相关处理 |
| `cmdb_hostserver` | `60001` | 主机数据维护 |
| `cmdb_operationserver` | `60011` | 运营统计相关功能 |
| `cmdb_procserver` | `60003` | 进程数据维护 |
| `cmdb_taskserver` | `60012` | 异步任务管理 |
| `cmdb_toposerver` | `60002` | 模型、业务拓扑及实例数据维护 |
| `cmdb_webserver` | `8083` | Web 页面和请求代理 |
| `cmdb_synchronizeserver` | `60010` | 数据同步，按需启动 |
| `cmdb_cloudserver` | `60013` | 云资源和云账号同步，按需使用 |
| `cmdb_authserver` | `60014` | 鉴权相关服务，按需使用 |
| `cmdb_cacheservice` | `50010` | 缓存服务，按部署方式使用 |
| `cmdb_transferservice` | `50011` | 数据传输同步，按需使用 |

### 3.2 服务与依赖关系

#### `cmdb_adminserver`

启动时会读取配置并连接：

- ZooKeeper
- MongoDB 主库
- MongoDB watch 库
- Redis
- IAM（启用鉴权时）
- ESB/GSE 相关接口（涉及对应功能时）

它负责配置中心初始化和数据库迁移，是启动流程中的关键服务。

#### `cmdb_coreservice`

主要依赖：

- ZooKeeper
- MongoDB
- Redis

它提供核心资源管理接口，其他场景服务通常通过服务发现访问它。

#### `cmdb_apiserver`

主要依赖：

- ZooKeeper
- Redis
- 其他 CMDB 服务的注册信息

#### `cmdb_webserver`

主要依赖：

- ZooKeeper
- Redis
- `cmdb_apiserver`
- PaaS/Login/ESB（取决于登录模式）

WebServer 会将登录 Session 保存在 Redis 中。独立部署时，通常通过服务发现访问 `cmdb_apiserver`。

#### `cmdb_toposerver`

主要依赖：

- ZooKeeper
- Redis
- `cmdb_coreservice` 提供的核心数据接口
- Elasticsearch（开启全文检索时）
- IAM（启用鉴权时）

#### `cmdb_datacollection`

主要依赖：

- ZooKeeper
- MongoDB
- 主 Redis
- `redis.snap`
- `redis.discover`
- `redis.netcollect`
- ESB
- Kafka（快照上报模式配置为 `kafka` 时）
- IAM（启用鉴权时）

默认快照模式为 Redis，因此最小启动不需要 Kafka：

```yaml
datacollection:
  hostsnap:
    reportMode: redis
```

#### `cmdb_eventserver`

主要依赖：

- ZooKeeper
- MongoDB
- Redis
- GSE（开启主机身份下发时）
- API Gateway（使用 GSE v2 或相关网关接口时）

#### `cmdb_cloudserver`

主要依赖：

- ZooKeeper
- MongoDB
- Redis
- bk-secrets（开启云账号加密时）

## 四、源码编译依赖

### 4.1 后端编译环境

当前 [go.mod](../go.mod) 声明：

```text
go 1.25.0
```

建议使用：

- Go `1.25.x`
- Python 3
- GNU Make
- Bash
- Git
- `wget`
- `tar`
- C/C++ 编译工具链
- 网络访问能力，用于下载 Go modules

Go 第三方依赖由 [go.mod](../go.mod) 和 `go.sum` 管理，执行以下命令下载：

```bash
go mod tidy
```

如果下载较慢，可以配置：

```bash
go env -w GOPROXY=https://goproxy.cn,direct
```

### 4.2 铜锁 Tongsuo

源码默认构建会执行 `scripts/tongsuo.sh`，准备 Tongsuo `8.3.2`。默认安装路径为构建目录下的 `tongsuo`，可以通过 `TONGSUO_PATH` 覆盖。

如果只是运行已经编译好的二进制，一般不需要重新安装 Tongsuo。

也可以在编译时关闭加密相关构建：

```bash
cd src
make DISABLE_CRYPTO=true
```

是否可以关闭取决于实际使用的服务和功能，生产环境不要在未确认影响的情况下关闭。

### 4.3 前端编译环境

当前 [src/ui/package.json](../src/ui/package.json) 的 `engines` 要求：

- Node.js `>= 18.18.0`
- npm `>= 9.8.1`

安装和编译：

```bash
cd src/ui
npm install
npm run build
```

项目中的旧编译文档仍推荐 Node.js 14，但和当前 `package.json` 不一致，应优先以当前 `package.json` 为准。

src/bin/pub/cmdb.tar.gz

## 七、本地启动流程

以下流程适合已有构建产物的情况。构建产物可以来自 Release 包，也可以来自 `make`。

### 7.1 启动 MongoDB

MongoDB 必须启用 Replica Set。示例：

```bash
mongod --dbpath ~/data/mongodb/cmdb \
  --replSet rs0 \
  --bind_ip 127.0.0.1 \
  --port 27017
```

连接 MongoDB 后初始化 Replica Set：

```javascript
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "127.0.0.1:27017" }
  ]
})
```

如果启用了 MongoDB 用户认证，需要创建具有 `cmdb` 数据库读写权限的用户，例如：

```javascript
use cmdb
db.createUser({
  user: "cc",
  pwd: "cc",
  roles: [
    { role: "readWrite", db: "cmdb" }
  ]
})
```

### 7.2 启动 Redis

```bash
redis-server --port 6379
```

项目初始化脚本要求配置 Redis 密码，建议为 Redis 设置 `requirepass`，并在后续 `init.py` 中填写相同密码。

### 7.3 启动 ZooKeeper

确保 ZooKeeper 可以访问：

```text
127.0.0.1:2181
```

### 7.4 初始化配置

进入构建产物根目录，执行：

```bash
python init.py \
  --discovery 127.0.0.1:2181 \
  --database cmdb \
  --redis_ip 127.0.0.1 \
  --redis_port 6379 \
  --redis_pass '<Redis密码>' \
  --mongo_ip 127.0.0.1 \
  --mongo_port 27017 \
  --mongo_user '<MongoDB用户名>' \
  --mongo_pass '<MongoDB密码>' \
  --blueking_cmdb_url http://127.0.0.1:8083 \
  --blueking_paas_url http://127.0.0.1 \
  --listen_port 8083 \
  --auth_scheme internal \
  --auth_enabled false \
  --full_text_search off \
  --user_info admin:admin
```

`init.py` 会生成或更新：

```text
cmdb_adminserver/configures/common.yaml
cmdb_adminserver/configures/mongodb.yaml
cmdb_adminserver/configures/redis.yaml
cmdb_adminserver/configures/migrate.yaml
cmdb_webserver/web.yaml
monstache/etc/config.toml
monstache/etc/extra.toml
```

其中：

- `migrate.yaml` 用于 AdminServer 读取注册中心、配置中心和迁移相关配置
- `common.yaml` 包含通用功能配置
- `mongodb.yaml` 包含主库和 watch 库配置
- `redis.yaml` 包含主 Redis 以及采集相关 Redis 配置
- `web.yaml` 包含 WebServer 配置

### 7.5 启动服务

```bash
./start.sh
```

需要同步服务时：

```bash
./start.sh --with-synchronize
```

### 7.6 初始化数据库

确认 CMDB 服务启动后执行：

```bash
./init_db.sh
```

成功时应看到类似结果：

```json
{"result":true,"bk_error_code":0,"bk_error_msg":"success","data":"migrate success"}
```

### 7.7 访问页面

```text
http://127.0.0.1:8083
```

### 7.8 停止或重启

```bash
./stop.sh
./restart.sh
```

## 八、前端开发模式

前端开发服务器默认监听 `9090`：

```bash
cd src/ui
npm install
npm run dev
```

开发配置位置：

```text
src/ui/builder/config/index.js
```

关键配置：

- 开发服务器：`localhost:9090`
- API 前缀：`/proxy/`
- 默认代理目标：`http://{webserver地址}/`

需要把代理目标改成实际 WebServer 地址，例如：

```text
http://127.0.0.1:8083/
```

前端 Mock 模式：

```bash
npm run dev -- --mock
```

Mock 模式只适合 UI 开发，不能代替完整后端服务。

## 九、配置检查清单

### 9.1 ZooKeeper

- [ ] 地址和端口可连接
- [ ] 如果启用了认证，用户名和密码正确
- [ ] 如果启用了 TLS，证书路径和校验参数正确
- [ ] `migrate.yaml` 中 `configServer` 和 `registerServer` 地址一致且正确

### 9.2 MongoDB

- [ ] MongoDB 进程正常运行
- [ ] Replica Set 名称与配置一致，默认是 `rs0`
- [ ] Replica Set 已经初始化并且存在 Primary
- [ ] `cmdb` 数据库用户具有读写权限
- [ ] `mongodb.yaml` 中主机、端口、用户名、密码、数据库名正确
- [ ] MongoDB `mechanism` 通常配置为 `SCRAM-SHA-1`

### 9.3 Redis

- [ ] Redis 地址和端口可连接
- [ ] 密码和 `init.py` 参数一致
- [ ] 如果使用 Sentinel，`masterName`、Sentinel 地址和密码正确
- [ ] 主 Redis、`snap`、`discover`、`netcollect` 配置可用

### 9.4 Web 配置

检查 `common.yaml` 或 `web.yaml` 中：

- [ ] `webServer.site.domainUrl` 与实际访问地址一致
- [ ] `webServer.login.version` 与登录方式一致
- [ ] 独立部署可使用 `opensource`
- [ ] 使用蓝鲸统一登录时需要 PaaS/Login 配置
- [ ] `webServer.site.htmlRoot` 指向实际 Web 静态资源目录

### 9.5 可选组件

- [ ] 开启全文检索时，Elasticsearch 地址、认证信息和 Monstache 配置正确
- [ ] 使用 Kafka 模式时，Kafka brokers、Topic、GroupID 和账号密码正确
- [ ] 启用 IAM 时，IAM 地址、App Code、App Secret 正确
- [ ] 开启主机身份下发时，GSE API 地址和证书配置正确
- [ ] 开启 cloud cryptor 时，bk-secrets 地址、Token、Project 和 Env 均已配置

## 十、常见问题

### 10.1 `ReplicaSetNoPrimary`

通常原因：

- MongoDB 没有使用 `--replSet rs0`
- 未执行 `rs.initiate(...)`
- Replica Set 配置中的主机地址不可达
- CMDB 的 MongoDB 配置和实际 MongoDB 地址不一致

### 10.2 服务启动后无法访问

检查：

- `cmdb_webserver` 是否正常运行
- WebServer 监听端口是否和 `--listen_port` 一致
- `webServer.site.domainUrl` 是否写成了正确地址
- `webServer.site.htmlRoot` 是否指向存在的静态资源目录
- 查看各服务 `logs/std.log` 和对应的错误日志

### 10.3 前端依赖安装失败

优先检查：

- Node.js 是否满足当前 `package.json` 的 `18.18.0+` 要求
- npm 是否满足 `9.8.1+` 要求
- 是否能访问 npm registry
- 是否有足够内存编译 `fibers` 等旧依赖
- 是否需要切换到可用的 npm 镜像

### 10.4 `cmdb_authserver` 启动失败

如果没有部署蓝鲸权限中心，或者没有启用 IAM 鉴权，通常可以先关闭鉴权功能。独立本地启动建议：

```text
--auth_scheme internal
--auth_enabled false
```

### 10.5 重新执行 `init.py` 后配置没有生效

重新生成配置后，需要重启所有 CMDB 服务进程：

```bash
./restart.sh
```
